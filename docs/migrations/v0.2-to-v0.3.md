# Migration Plan: v0.2 Runtime to v0.3 Federation

Status: Architecture plan; implementation incomplete

## Non-negotiable rule

No big-bang rewrite. The verified v0.2 runtime remains deployable while v0.3 capabilities are introduced behind compatible boundaries.

## Compatibility anchors

- local HTTP control plane;
- Job, Run, Session, Project, and Trace separation;
- bounded fan-out;
- timeout, output limit, and confirmed cancellation;
- normalized events and SHA-256 artifacts;
- local configuration and preflight;
- fail-closed unsupported capabilities;
- loopback-first network default and explicit authentication for non-loopback use.

## Work packages

### M01 — Source and contract audit

Map every v0.2 public API, schema, adapter primitive, test, and deployment script. Publish incompatibilities before changing behavior.

### M02 — Eight-harness census

For H01-H08, record official source, version command, platform, authentication, headless interface, structured output, session, cancellation, workspace, artifact, usage, and license evidence. Initial state remains `DECLARED_UNVERIFIED` until local evidence exists.

### M03 — Registry and capability model

Replace the static adapter inventory with a versioned registry while preserving `config/harnesses.local.json` as a compatibility input.

### M04 — Adapter Contract experiments

Map Codex, Hermes, and DeepSeek candidates to the draft v0.3 operations. Do not change the released v0.1 contract until schemas and conformance tests are approved.

### M05 — Combat Passport

Implement the fourteen gates and produce machine-readable evidence per adapter and platform.

### M06 — Worktree isolation

Allocate a distinct writable worktree or sandbox per Run. Preserve partial success without permitting concurrent filesystem collisions.

### M07 — Artifact intake and telemetry

Normalize patches, tests, logs, SHA-256 artifacts, limitations, trace identity, timing, retries, and available usage or cost data.

### M08 — Joint review workflow

Build Lead, Submission, Collaborator Review, Red Team, Rework, Joint Integration, and Acceptance stages on top of v0.2 fan-out.

### M09 — Native adapters

Add H02/H03/H04/H06/H07/H08 one at a time. Each adapter requires official-interface evidence, isolation, failure semantics, and conformance results. No batch claim of eight-adapter support is allowed.

### M10 — Optional Cogiens projections

Add control-plane, map, trace, and business-system projections last and keep commercial modules outside the MIT public core.

## Release gates

| Release | Minimum evidence |
|---|---|
| `v0.3.0-architecture-freeze` | Public RFC, draft contract, registry, migration plan, boundary scan, CI |
| `v0.3.0-alpha.1` | Registry implementation, census data model, tests, at least one evidence-backed v0.3 adapter path |
| `v0.3.0-beta.1` | Isolation, Combat Passport, artifact intake, joint workflow, multi-platform tests |
| `v0.3.0` | Stable contract, migration evidence, security review, upgrade/rollback, no unresolved critical gaps |

## Rollback

Every implementation PR must leave the prior v0.2 behavior accessible until the new path passes its acceptance gates. A failed adapter or workflow stage must be disableable without removing the verified local gateway.
