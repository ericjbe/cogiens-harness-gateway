# 水枢产品规格书

编号：SHUISHU-PRD-V3-001  
产品：水枢 · Cogiens Workforce OS  
版本：V3.1（Harness 模型管理与执行基线）  
日期：2026-09-09  
状态：内部开发基线；须经 Doctor 验收后冻结

## 1. 产品定义

水枢不是某一个应用的附属页面，也不是一个只会回答问题的聊天机器人。水枢是 Cogiens 的公共人工智能执行基础设施：统一发现、选择、授权、调度、执行和验收大模型 Harness，并把模型、工具、文件、代码、任务、费用和工程产物组织成一条可追溯的生产流水线。

现有 APP 是客户入口，现有 CP 是平台管理与多租户授权入口。水枢不得复制 APP、CP、账户、角色、计费或文件服务；水枢通过插件、API、SDK 和适配器复用这些公共设施。各业务应用应成为水枢的插件或调用方，不能反过来把水枢做成某个应用的插件。

水枢可以被理解为 Cogiens 自己的“聚合大模型”：模型提供认知能力，Harness 提供工具和行动能力，水枢提供治理、编排、证据与交付能力。

## 2. 首期目标

V3.1 首期必须交付一个可以实际使用的“大模型与 Harness”一级栏目，支持：

1. 动态展示目标 10 个本地免费模型席位及其真实状态；
2. 展示 6 个收费模型服务族及其 Harness 接入状态；
3. 将模型、Harness、执行节点组合成可验证的执行组合；
4. 从水枢创建真实任务，选择一个或多个执行组合；
5. 显示排队、执行、失败、取消、完成和待验收状态；
6. 提供文字输出、真实文件、Git patch、日志和测试报告等产物入口；
7. 通过现有 APP/CP 控制租户可见模型、预算、项目与工作区边界；
8. 先让至少一个免费模型与一个具备文件/命令能力的 Harness 执行水枢自身的未完成工单，不等待所有模型接完。

## 3. 非目标与禁止事项

- 不新建第二套 APP、CP、登录、租户、计费或文件中心。
- 不把“模型已下载”写成“模型可以工作”。
- 不把“模型能生成文字”写成“Harness 能修改代码”。
- 不把界面上的预设卡片写成真实在线能力。
- 不允许浏览器提交任意命令、任意模型地址、API Key、工作目录或服务器路径。
- 不允许未授权的自动付费升级。
- 不允许用 HTTP 200、进程启动或模型自称完成代替文件、测试和业务验收。
- V3.1 不宣称蒸馏、预训练和客户生产开放已经完成；这些是后续能力域。

## 4. 用户与权限

### 4.1 超级管理员

超级管理员使用现有 CP 身份，能够查看全部模型和 Harness 状态、配置适配器引用、设定租户策略、批准收费预算、停用异常组合、查看全局审计证据。凭据本身不得在水枢页面回显。

### 4.2 平台工程师

平台工程师只能在授权项目和工作区内创建、观察、取消及验收任务；不得改变租户身份、平台级预算或生产凭据。

### 4.3 租户管理员与租户用户

租户管理员通过现有 APP/CP 获得经服务端签发的模型、Harness、预算和项目范围。租户用户只能看到授权后的执行组合，只能读取本租户任务与产物。前端隐藏不是权限控制，所有过滤必须在服务端执行。

### 4.4 审核者

审核者能够查看任务输入、执行证据、变更、测试和费用，但不能自动获得修改文件或重新执行的权限。

## 5. 模型与 Harness 的基本关系

模型、Harness 和节点是三个独立对象：

- 模型回答“由谁推理”；
- Harness 回答“能使用哪些工具、如何行动”；
- 节点回答“在哪里执行、能够访问什么资源”。

只有三者形成经过服务端校验的执行组合，任务才可选择。模型名称不得直接推导代码、文件、联网、浏览器、取消或流式能力。

## 6. 模型目录

### 6.1 本地免费模型池

界面设置 10 个目标席位，但席位内容必须来自 M3 的真实 Ollama 清单与水枢配置，不在前端写死。每个模型至少显示：

- 模型显示名与实际模型标识；
- 所在节点、资源类型与量化信息（可取得时）；
- 已发现、已安装、推理验证、Harness 工具验证和稳定性状态；
- 最近验证时间、耗时、错误摘要及证据引用；
- 可处理任务类型、上下文和资源限制；
- 当前是否可选，以及不可选的明确原因。

模型数量不足 10 个时，空缺席位显示“待接入”；实际发现超过 10 个时进入候选池，由管理员配置进入生产目录。不得删掉或隐藏真实失败记录来凑齐 10 个“绿色模型”。

### 6.2 收费模型服务池

首期管理 6 个目标服务族：OpenAI、Anthropic Claude、xAI Grok、Moonshot Kimi、DeepSeek、Alibaba Qwen。这里登记的是服务族和已安装 Harness，不固定声称某一个模型永久“最先进”。具体模型标识由服务端配置和定期能力验证决定。

每个收费模型至少显示：

- 服务商、Harness、实际模型标识和接入方式；
- 凭据状态（仅显示已配置/未配置，不显示秘密）；
- 额度、预算策略、计量来源和费用状态；
- 可用区域、租户范围、数据处理限制；
- 最近连接、推理和工具执行证据；
- 当前是否允许执行，以及阻塞原因。

个人会员或网页登录状态不能自动解释为面向平台和租户的 API 服务授权。

## 7. Harness 目录

水枢沿用已登记的 H01-H08 一等 Harness，并允许标准插件适配：

- H01 OpenAI Codex
- H02 Anthropic Claude Code
- H03 xAI Grok Build
- H04 Moonshot Kimi Code
- H05 DeepSeek Harness
- H06 Qwen Code
- H07 Google Antigravity CLI
- H08 Mistral Vibe

上述名称表示治理目录，不表示当前全部安装或通过验证。每个 Harness 必须登记：版本、来源、原生协议、安装节点、工具能力、文件读写边界、命令执行边界、联网边界、超时、取消、重试、并发、输入输出、产物类型、健康检查与回滚方式。

外部 Harness 优先通过 MCP、OpenAPI、HTTP/Webhook、官方 SDK 或原生 CLI 适配，不要求改写为水枢私有实现。兼容范围必须逐项标明，不允许笼统写“全部兼容”。

## 8. 管理执行界面

### 8.1 总览

显示免费模型可用数、收费模型可用数、Harness 可用数、执行节点、排队任务、运行任务、当日费用和待验收任务。统计值必须来自实时接口；接口失败时显示“未知/不可用”，不得保留旧值伪装实时状态。

### 8.2 大模型与 Harness

使用“全部、本地免费、收费先进、待接入、异常”筛选。卡片或表格同时显示模型、Harness、节点、能力、验证、费用和选择状态。允许查看组合详情和证据。

### 8.3 任务派发

任务表单至少包含项目、授权工作区、任务要求、验收条件、模型/Harness 组合、优先级和费用策略。工作区必须来自服务端授权列表，不能由浏览器提交任意绝对路径。

首期支持显式选择，不启用无授权的自动收费降级。允许策略：只用免费、免费优先且预算内升级、指定收费组合；后两者只有在 CP 已签发预算授权时才可使用。

### 8.4 队列与运行

显示任务依赖、排队原因、当前步骤、执行节点、已用时间、重试、取消能力及原始错误。相同工作区的写任务默认串行；不同工作区可在资源和权限允许时并行。

### 8.5 结果与验收

结果页区分模型文字、真实文件、Git patch、构建包、日志、测试报告和结构化数据。每个产物必须绑定 job_id、run_id、trace_id、实际适配器与版本、SHA-256、大小和生成时间。

“执行成功”只表示执行器正常结束；“工程验收通过”还必须满足规定的文件、测试和审核条件。失败、取消和超时任务也要保存已有的部分产物并标明不完整。

### 8.6 租户策略

此页作为现有 CP 的插件视图，不形成新后台。管理员配置租户可见组合、项目、并发、月度预算、单任务上限、数据区域与允许的工具能力。水枢只消费可信授权结果。

## 9. 状态模型

模型与 Harness 状态不得合并为一个“在线”灯：

1. REGISTERED：已登记；
2. DISCOVERED：实际发现安装或服务；
3. CONNECTABLE：端点或进程可连接；
4. INFERENCE_PASS：真实推理通过；
5. HARNESS_PASS：真实工具任务通过；
6. STABLE：达到规定重复测试门槛；
7. PRODUCTION_READY：权限、计费、隔离、回滚和验收均通过；
8. BLOCKED/FAILED/EXPIRED：失败、证据过期或策略禁止。

任何较高状态都必须引用证据及有效期。新的失败证据可以撤销旧的绿色状态。

## 10. 调度策略

默认先使用满足任务能力的免费组合。选择依据依次为：权限、能力匹配、健康与证据、工作区和数据边界、队列、资源、费用。不能仅按模型名或排行榜调度。

复杂任务允许使用收费模型，但必须同时满足：现有身份授权、租户允许、有效凭据、预算充足、计量可记录、数据策略允许。任何一项不满足即阻止执行并说明原因。

多模型执行用于独立方案、审查或竞技，不默认让多个模型同时写同一工作区。写入合并必须经过隔离分支、差异审查和测试门槛。

## 11. API 与插件契约

首期保留并扩展以下契约：

- `GET /v1/model-harness/catalog`：返回经权限过滤的组合目录；
- `POST /v1/jobs/selected`：使用服务端登记的 choice_id 创建任务；
- `GET /v1/jobs/{job_id}`：读取授权任务及运行；
- `POST /v1/jobs/{job_id}/cancel`：按声明能力取消；
- `GET /v1/jobs/{job_id}/artifacts`：列出授权产物；
- 现有结果接口：通过公共文件服务提供受权下载；
- APP/CP SDK：传递可信身份、租户、项目、模型范围和预算授权；
- 插件注册接口：登记 Harness、能力、版本、证据和回滚信息。

任何 API 都不得接受浏览器提供的任意执行命令、基础 URL、明文凭据或未经授权的 tenant_id。

## 12. 安全、审计与费用

凭据只以安全引用进入适配器，禁止写入任务正文、日志、页面、Git patch 和产物。执行过程记录操作者、租户、项目、选择策略、模型、Harness、节点、工具调用、费用、结果和验收人。

本地免费指不产生模型服务调用费用，不表示没有电力、硬件、维护和机会成本。收费模型必须记录可取得的输入/输出计量、费用估算与账单对账状态；缺少可靠计量时不得对客户展示为已完成计费。

## 13. 多租户验收门槛

客户版本开放前必须证明：

- 复用现有 APP/CP 登录，无第二账户；
- 两个租户无法读取、取消或下载对方任务和产物；
- 租户看不到未授权模型和 Harness；
- 超预算、无凭据、凭据失效和费用接口失败均拒绝收费执行；
- 工作区路径由服务端授权，不能越界或使用链接逃逸；
- 正常、失败、超时、取消和部分产物场景均有证据；
- 管理操作、授权变化和费用变化可审计。

在这些证据完成前，`customer_access_ready` 必须保持 `false`。

## 14. 首期验收

V3.1 只有满足以下条件才可以称为“可用内部版”：

1. 页面能够展示实际目录，10 个免费和 6 个收费目标席位均有诚实状态；
2. 至少一个免费模型完成真实推理验证；
3. 至少一个 Harness 完成文件读取、文件写入、命令执行和测试产物收集；
4. 从界面创建水枢自身工单，产生可下载的真实 patch、文件、日志和测试报告；
5. 失败时显示真实错误，不生成伪成功产物；
6. 全量自动测试通过，保留测试命令、退出码和报告；
7. M3 隔离工作树复验通过后才合入；
8. 香港部署只能在内部版本验收和回滚准备完成后进行。

## 15. 后续能力域

在执行基础设施稳定后，水枢进入三个后续阶段：

1. 多模型审查、竞技、共识和预算优化；
2. 业务应用以插件方式全面接入水枢；
3. 将高质量任务、工具轨迹、失败样本、修订和验收结果沉淀为经治理的数据资产，用于授权范围内的蒸馏、微调和预训练。

训练数据建设必须另行建立来源、权利、隐私、脱敏、质量、版本和删除策略。生产任务记录不能因为“将来训练”而自动变成训练数据。

## 16. 当前事实基线

截至 2026-09-09：水枢本地首张工程产物收集工单已经完成代码开发，相关专项测试及全量校验通过；修改尚未同步到 M3。现有 V3 已具备模型/Harness 目录与显式选择的基础代码，但 10 个本地免费模型、6 个收费服务、客户身份、计费及生产执行状态仍须按本规格逐项接入和验证。

本规格书定义产品形态和共同开发基调，不把目标计划冒充已经部署的事实。
